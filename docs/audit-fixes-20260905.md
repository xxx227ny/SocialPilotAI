# SocialPilot 审查问题修复说明

日期：2026-09-05。基于 `07af1dc` 后的本地工作区修改。

## 已完成的代码修复

1. **图片重试不再提前产生孤立任务**：检查全部镜头状态后再入队；替代任务先 flush，不单独提交，和批次引用一同提交。异常会回滚未提交的替代任务。首次图片入队也使用同一提交方式。
2. **镜头与图片按身份匹配**：按 scene_sequence 对应脚本镜头，拒绝重复或缺失镜头，避免重试后的新任务编号改变画面顺序。
3. **增加后台推进**：现有 execution worker 每隔约 15 秒检查已确认费用的活动生产批次，沿原流程推进。正在执行单个任务时，本次任务结束后再检查。无需网页保持打开，重启工作器后也会重新发现活动批次。
4. **保护后台与网页并发操作**：推进、暂停、恢复、取消共享跨进程批次锁；异常退出由操作系统释放锁。当前适配项目实际使用的单主机 SQLite 部署（Windows / Linux 分支），不是多主机分布式调度方案。
5. **后台遵守原有边界**：不新建用户未提交的批次，不推进未确认费用、暂停、取消、完全失败或已完成的批次；部分平台失败时，只继续其他活动平台，不自动重试失败平台。启用用户认证时，只使用商品所属工作区已验证的供应商凭据，并在退出上下文时清除绑定。
6. **运行配置保留**：重新生成配置会保留明确允许的社交平台 OAuth 配置、绑定/发布开关、令牌加密密钥及密钥版本；仍不会复制共享的 Qwen/Wanx 生成密钥。SMTP 保留逻辑继续有效。
7. **社交前端开关可配置**：产品构建接受显式 `SOCIALPILOT_SOCIAL_FEATURES` 列表，不再只能固定关闭。默认仍关闭，防止把未配置的平台展示为可用；未知名称会使构建失败，不会静默忽略。
8. **测试入口统一**：从 backend 目录运行 pytest 无需额外设置 PYTHONPATH；前端新增 `npm test`，自动发现所有 `test-*.mjs`，防止测试脚本遗漏。
9. **清理遗留 UI**：移除 5 个没有页面消费者的旧面板（高级脚本外壳、脚本编辑器、初始蓝图、手动合成、旧万相演示），清除不可达分支及已被队列测试替代的旧测试。相关有效状态/API 行为测试保留；后台蓝图、渲染、合成服务未删除。删除文件可从 Git 的原版本恢复。
10. **兼容性小修**：账号接口不再访问已弃用的 HTTP 422 常量，HTTP 返回值不变；旧交接文档标注为历史状态。

## 社交构建配置示例

只有服务器端应用凭据、准确回调地址和所需平台权限配置完成后，才启用对应入口。此操作不是连接账号本身，也不会自动发布。

PowerShell（仅开启 YouTube 绑定和发布界面）：

```powershell
$env:SOCIALPILOT_SOCIAL_FEATURES = 'SOCIAL_ACCOUNT_BINDING,YOUTUBE_PUBLISHING'
npm run build:product
Remove-Item Env:SOCIALPILOT_SOCIAL_FEATURES
```

Linux：

```sh
SOCIALPILOT_SOCIAL_FEATURES=SOCIAL_ACCOUNT_BINDING,YOUTUBE_PUBLISHING npm run build:product
```

可用项：SOCIAL_ACCOUNT_BINDING、INSTAGRAM_ACCOUNT_BINDING、TIKTOK_ACCOUNT_BINDING、PINTEREST_ACCOUNT_BINDING、YOUTUBE_PUBLISHING、INSTAGRAM_PUBLISHING、TIKTOK_PUBLISHING。服务器端仍独立校验功能开关、凭据和权限，前端开关不能绕过这些检查。

## 上线注意事项

- 本次没有修改线上服务、数据库、平台账号或密钥，也没有进行付费生成或真实发布。
- 无新增数据库迁移。上线需要正常构建并部署新代码，重启 API 与工作器。
- 数据库目录需允许 API 与工作器共同使用的服务账号写入 `.production-locks`。现有 staging 服务使用同一账号且允许写入该目录。锁文件不可在服务运行中随意删除。
- 新工作器会继续已经确认费用的活动批次，因此上线前应核对是否存在仍应执行的活动任务；本轮未操作这些线上任务。
- 外部 OAuth、真实邮件投递、付费成片生成和社交发布不在本轮自动化验收范围内，不能声称已重新完成实网验收。
- 第三方 Starlette/httpx 测试适配层仍有一条弃用提示；未以屏蔽警告或贸然升级依赖的方式处理，不影响本轮测试通过。
