# SocialPilot AI 复赛演示视频脚本

推荐时长：5 分钟。录制时使用普通工作台，不使用旧的便携榨汁机预置快照冒充当前产品闭环。

## 录制前门禁

- [ ] 后端 8000、前端 5173 正常。
- [ ] 商品、品牌规范、商品图均已准备。
- [ ] 四平台文案矩阵已生成。
- [ ] TikTok、YouTube Shorts、Instagram Reels 三个平台均有可播放成片。
- [ ] 批次 ZIP 包含 3 个 MP4、3 个 WebVTT 和清单。
- [ ] 投流商品已有四平台 CSV 数据和可展示 ROAS。
- [ ] 录制过程中不执行真实模型调用；只展示前置检查、费用和已保存结果。

如果 TikTok 未恢复，不得录制“3/3完成”版本。

## 0:00–0:25｜问题与产品

**画面**：总览和左侧四个独立工作区。

**讲解**：

“SocialPilot AI 面向跨境电商团队，把社媒内容生产和投流优化放进一个可追踪系统。商家只需要准备商品信息和商品图，系统就能生成多平台文案、短视频，并把广告数据转成可控的预算和竞价方案。”

## 0:25–1:10｜商品中心

**画面**：商品中心，展示一个非榨汁机商品、品牌规范版本和商品主图。

**讲解**：

“项目不是围绕单一商品写死。商品、品牌规范和素材都独立保存，后续文案、脚本、视频和投流记录通过精确编号关联。这里展示的是第二种商品，用来证明多商品通用性。”

## 1:10–2:00｜目标 2：四平台文案矩阵

**画面**：文案矩阵页面，依次滚动 TikTok、Instagram、Facebook、Pinterest。

**讲解**：

“千问根据同一商品和营销策略，生成四个平台不同语气的文案。每个平台都有开场钩子、正文、话题标签和行动号召。结果可以逐条复制、整套复制，也可以导出 JSON 或 CSV。重新生成会保留旧版本并再次确认费用。”

现场点击一次“导出 CSV”或“复制整套文案”，不要点击真实重新生成。

## 2:00–3:20｜目标 1：三平台短视频批量生产

**画面**：视频工厂，展示批次编号、三平台卡片和 3/3 已完成状态。

**讲解**：

“同一商品被编排为 TikTok、YouTube Shorts 和 Instagram Reels 三个独立变体。千问生成平台脚本，商品动态视频模型生成真实运行画面，千问 TTS 生成旁白，系统再完成字幕、音乐、混音和竖屏成片。三个平台独立推进，一个失败不会阻塞或删除其他结果。”

依次播放三条视频的关键 3–5 秒，重点展示：

- 商品主体完整可见；
- 商品处于真实使用或运作状态；
- 旁白完整说明卖点；
- 字幕与旁白同步；
- 平台表达存在差异。

最后点击批量下载，展示 ZIP 中的 MP4、WebVTT 和清单。

## 3:20–4:35｜目标 3：ROAS 投流沙箱

**画面**：投流优化页面，选择商品 `#2`。

**讲解**：

“广告数据通过 CSV 导入，CTR、CVR、CPA 和 ROAS 都由确定性代码计算，不让模型编数字。当前总体 ROAS 是 2.35 倍；Facebook 1.40、Instagram 2.00、Pinterest 2.60、TikTok 3.10。系统可以把这些数据和精确内容链交给千问生成受约束建议，再由确定性预算算法形成内部方案。”

继续展示总预算、目标 ROAS、沙箱前置检查、紧急停止、单平台变化上限和监控周期。

**必须说明**：

“当前执行是安全沙箱，不连接、不修改真实广告账户。这样既能证明方案可执行，也避免比赛演示误操作真实投放。”

## 4:35–5:00｜技术与价值总结

**画面**：回到总览或架构图。

**讲解**：

“千问负责商品理解、策略、脚本、文案和投流建议；万象与商品动态视频模型负责视觉生成；千问 TTS 负责语音；系统自己的任务状态机、幂等、版本冻结和安全沙箱负责把 AI 能力变成稳定产品。SocialPilot AI 让一个小团队可以从商品出发，一次完成内容矩阵、视频矩阵和增长反馈闭环。”
