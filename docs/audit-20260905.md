后续状态：已按用户授权进行本地修复，详见 `audit-fixes-20260905.md`。本文保留审查时的发现与测试证据，不代表修复后的状态。

## 结论

发现两项已隔离复现的视频重试缺陷，以及后台推进、社交配置保留、测试入口和遗留界面代码方面的问题。测试大部分通过不代表真实生成、OAuth 和浏览器交互已经全部验收。

## 按优先级排列的问题

### 1. 高：重试失败后可能留下未关联的新图片任务

位置：`backend/app/services/product_video_production_batch_service.py`，`_prepare_wanx_image_recovery`（约 360–440 行）。

函数逐个检查并重建镜头任务：如果前一个镜头失败，就先入队替代任务；若后一个镜头仍在运行或状态不确定，则提前返回失败。新任务已经提交，但新的任务编号尚未保存到生产批次中。

隔离控制流复现：旧任务 `[11 FAILED, 12 RUNNING]`，替代任务返回 `13`；恢复返回 `False`，实际已入队一次，批次仍引用 `[11, 12]`。没有调用真实供应商。

影响：后台可能执行批次未追踪的额外任务，产生不必要调用和潜在费用。建议先验证全部镜头是否满足恢复条件，再创建任务并可靠保存关联。

### 2. 高：部分镜头重试成功后可能用错图片

位置：同文件 592 行按 `ExecutionJob.id` 排序、622 行收集素材、663 行按镜头顺序配对素材。

重试后的任务编号顺序不再等同于镜头顺序。例如第一个镜头重试后编号较大，第二个镜头沿用较小编号；按编号排序会颠倒图片。

内存数据库复现：镜头对应任务 `[3, 2]`，预期素材 `[3, 2]`，实际素材 `[2, 3]`。现有重试测试只覆盖重新入队，没有覆盖重试完成后的下一阶段。

影响：可能完成生成但画面与脚本错配。建议按镜头身份匹配素材，不能依赖任务编号顺序，并补充部分重试后继续生产的测试。

### 3. 中：完整生产仍依赖网页推进

位置：`frontend/src/components/video/RealProductVideoPanel.tsx` 的 `driveProductionBatch`（约 1325 行）；后端 `ProductVideoProductionBatchService.advance`。

前端循环调用推进接口，组件卸载会停止循环。后端工作器处理已入队任务，但未发现独立推进生产批次到下一阶段的调度器。读取批次及定时刷新是只读操作。

影响：关闭或离开页面后，已入队任务可以完成，但下一阶段可能等待用户返回并继续推进。此项为代码路径检查结论，未执行真实付费批次的关页实验。

建议：将完整流程推进放入后台；前端只提交、显示进度与控制暂停/取消。

### 4. 高（接入前必须处理）：重新生成运行配置会丢失社交配置

位置：`deploy/staging/configure_runtime.py:45`，`build_runtime_config`。

该函数重建配置，只保留部分现有字段。用虚构凭据做内存测试，Google OAuth 客户端配置及社交令牌加密密钥均未保留，社交绑定开关变为 false，而 SMTP 配置被保留。

影响：将来接好账号后，再运行该配置生成脚本可能关闭接入，并丢失解密既有社交令牌所需的密钥。这不等于每次普通部署都会发生，触发条件是重新运行配置生成脚本。

建议：明确保留现有凭据、加密密钥及功能开关；增加配置升级回归测试。

另有接入限制：`frontend/scripts/build-product.mjs` 清除外部 VITE 配置后，将社交绑定/发布开关固定为 false。因此只打开服务器开关仍不够，还需要调整并重新构建前端，或改为读取服务器能力状态。

线上只读检查确认：当前 YouTube 绑定和发布均关闭，客户端凭据未配置；SMTP 已配置。这是尚未接入的状态，不应显示为已经支持真实连接。

### 5. 中：测试入口有遗漏与不兼容

- 从 backend 目录直接运行 pytest，`tests/test_staging_release_bundle.py:7` 找不到仓库根目录下的 deploy 模块，收集失败。加入仓库根目录 PYTHONPATH 后全量测试通过。应统一测试入口或修正 pytest 路径配置。
- `frontend/scripts/test-initial-video-project.mjs:61` 调用已不存在的 `canExecuteInitialVideoProject`，实际执行失败。该旧脚本未接入现行 npm 测试入口；现行 `test:initial-video` 指向新的队列测试。建议迁移有效断言或删除已被完整替代的旧脚本。
- 测试输出有 3 条弃用警告，涉及 TestClient/httpx 和旧 HTTP 422 常量。当前不是运行失败，升级依赖前应处理。

### 6. 低：存在不可达分支及未使用的高级页面组件

`frontend/src/pages/ContentStudioPage.tsx:91` 在非演示模式提前返回；后面的 117 行又要求非演示模式才能显示 LiveWanxGenerationPanel，该分支不可达，相关导入和条件可以清理。

在 frontend/src 中检索，AdvancedVideoScriptVersionPanel、InitialVideoProjectPanel、VideoCompositionPanel 未发现实际页面调用。与之前移除高级制作界面相符，可进一步确认测试价值后删除或归档。

不要据此删除后台蓝图、渲染、合成服务：它们可能仍被一键生产链路复用。旧交接文档的 SMTP 状态也已经落后于当前实际配置，应更新。

1. 修复视频重试原子性和镜头素材映射，并补足跨阶段回归测试。

5. 最后进行有费用确认的单平台生成，以及真实 OAuth、邮件与发布验收。
